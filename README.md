# TFC 锻造助手 · 批量版 v0.2.3

TerraFirmaCraft 1.21.1 的 Windows 外部辅助工具：自动定位实例、读取屏幕和砧 GUI，计算最短方案，并支持自动补料、逐件锻造和收回成品。系统进程信息用于定位目录，锻造状态从画面识别。

## 启动

**普通用户：** 从 [Releases](https://github.com/ChuanYuanNotBoat/tfc-forge-helper/releases/latest) 下载 `tfc-forge-helper-0.2.3-windows-x64.zip`，完整解压后双击 `TFC-Forge-Helper.exe`。支持 Windows x64，无需安装 Python。发布附件中的 `SHA256SUMS.txt` 可用于核对下载完整性。

**从源码运行：** 安装 Python 3.11+（含 Tk），双击 `start.cmd`。首次启动会建立本地虚拟环境并下载依赖。

EXE 版设置保存在 `%LOCALAPPDATA%\TFCForgeHelper\settings.json`，校准默认保存到同目录下的 `profiles` 文件夹；源码版沿用项目内的 `work/settings.json`。构建与发布步骤见 [docs/releasing.md](docs/releasing.md)。

更新后请先关闭旧版助手窗口，再运行新版 EXE（源码版双击 `start.cmd`），窗口标题应包含“批量版 v0.2.3”。工具默认开启连续识别，游戏已运行时自动从 Java 进程的 `--gameDir` / `-Duser.dir` 定位实例；启动器隐藏这些参数时，回退到进程工作目录。验证 `options.txt` 与 TFC JAR 后读取当前资源包，每 5 秒重新检查实例和资源配置。常见 Minecraft / Prism / MultiMC 目录作为后备。

- 按 **F8** 或点击“识别屏幕”读取当前状态。
- “连续识别”默认开启，每轮完成约 1 秒后再次识别。只有可靠识别到当前位置、目标、规则或最近历史发生变化时，才更新方案和小窗；匹配度浮动、窗口位置或缩放变化不会反复重绘同一方案。
- 鼠标指针、提示框或临时遮挡导致某帧无法识别时，保留上一次有效方案，直到下一次有效状态更新。后台识别不反复显示加载文字或低匹配度错误；暂停连续识别也保留当前显示。
- “小窗提示”显示下一步和完整方案，可以拖到砧 GUI 之外。
- 默认跟随游戏进程的可见窗口截图，支持游戏在其他显示器上；也可选择主屏或全部屏幕。
- 自动推断 GUI 位置和 1–8 倍整数缩放，移动窗口或改变 GUI scale 后无需重新设置。
- 多个 TFC 实例并存时，在候选列表中选择实例，并关闭“自动从进程定位”。

v0.2.1 修复游戏窗口部分移出屏幕时，清除提示框的鼠标停放点越界而无法启动批量的问题。停放点从游戏窗口与实际显示器的交集选择，支持负坐标显示器和显示器之间的空隙；真正动作点和点击后的停放点均在点击前验证，屏幕外的动作按钮不会被改到错误位置。

进程命令行只用于定位目录；不会保存或打印完整启动参数，以免暴露启动器的令牌。F8 是被动注册的全局热键，占用时仍可使用按钮。

## 自动打铁

首件原料放入砧并选好一次配方，点击“开始自动打铁（3 秒）”，然后切回游戏。**F9 随时停止**，窗口中的“停止”按钮也可结束执行。界面不再需要额外的启用勾选，只有点击开始才发送操作。若正在识别，会排队后自动开始倒计时。

“批量补料与收成”默认开启，数量 `0` 表示直到同类原料用完；也可填写指定数量。数量按原料件数计，包含已在砧上的首件。工具自动从背包和快捷栏寻找与首件图标相同的原料，优先使用快捷栏，逐件补入输入槽；源堆叠余料会放回原槽。

每件完成后按已选配方的成品图标确认结果，再通过游戏的 Shift 点击规则自动合并或收回背包。无需指定供料格或逐件重新选择加工目标；TFC 会记住所选成品。**每次补料后都重新识别该件的 current、target 和完整规则，并独立求解，允许每件随机目标和规则；不复用首件或上一件的操作序列。** 成品图标用于确认加工目标相同，规则可以变化。原料用完、背包装不下、物品过于相似无法区分或取放状态不符时停止。背包满时已锻造的成品保留在砧上；F9 若在原料转移中按下，鼠标可能仍持有原料，工具会提示手动放回。

当前坯料需要处于可加工温度并有可用锤子。批量模式不会自动加热；温度不足或锤子不可用会因状态没有变化而停止。关闭“批量补料与收成”可恢复单件执行。

**每件原料只在开始时识别一次 current、target、完整规则与历史，求出整套最短序列后按顺序执行；不再每步截图、识别和求解。** 本件结束后确认最终位置/历史或成品图标，再收成、补料并为下一件重新识别。锻造动作间固定等待从 160–180 毫秒缩短到 40 毫秒，仍保留鼠标按住时间；慢响应时在本件结束后等待确认，不会重复发送序列。模拟基准相对 v0.2.2，七步单件约快 2.46 倍、三件批量约快 3.41 倍；实机速度取决于帧率和服务器响应，详见 `docs/performance.md`。

批量取放取消固定停顿：点击后立即检查，原料已拿起、放入或余料已归位就继续，只有画面未更新时才等待。成品图标已经确认后直接收回，不再为同一成品重复截图；仍确认每次转移，不重试未确认的操作。

序列开始前校验 GUI 和所有要用到的按钮贴图；每次点击仍检查实例、资源、游戏前台、窗口位置和按钮是否被其他窗口遮挡。自动模式使用比辅助识别更严格的匹配阈值。焦点丢失、窗口移动、资源切换、F9、修改设置或退出工具都会中断执行；进度、历史与配方变化在本件结束时确认，结果不符或超时则停止，**不会自动重试点击或重发整套序列**。F9 无法注册时不会启动自动执行。

单件模式下，配方完成后指针可能消失，工具会停止并提示核对成品。批量模式另有成品图标确认流程；看不到指针本身不会触发自动取放。实际执行从窗口中的启动按钮开始，命令行只提供识别和求解。

## 手工求解

输入 `current`、`target`（0–150）、0–3 条规则，以及最近 0–3 步操作（**由旧到新**）。界面提供中文动作和规则选择。命令行使用 TFC 名称：

```powershell
.\.venv\Scripts\python.exe -m tfc_forge_helper solve --current 83 --target 108 --rules hit_third_last,draw_second_last,draw_last
```

该示例的最短方案是 7 步，所有中间位置均在 0–150 内。三种力度的击打都可满足 `hit` 规则，但对应位移不同。

| 动作 | 位移 |
| --- | ---: |
| hit_light / 轻击 | -3 |
| hit_medium / 中击 | -6 |
| hit_hard / 重击 | -9 |
| draw / 拉伸 | -15 |
| punch / 冲孔 | +2 |
| bend / 弯曲 | +7 |
| upset / 镦锻 | +13 |
| shrink / 收缩 | +16 |

规则形式为 `动作_位置`，动作有 `hit, draw, punch, bend, upset, shrink`；位置有 `any, last, not_last, second_last, third_last`。这些位置始终相对于最后三步，**规则列表的显示顺序不是强制执行顺序**。同一操作可以同时满足兼容规则。

历史留空表示从无可复用的最近操作开始求解。已操作的坯料应填写真实历史，或通过截图读取，否则不能保证相对于真实历史的最少剩余步数。默认贴图的三种击打历史图标完全相同，读取时统一显示为 `hit` 类别；历史力度不影响规则或最短剩余方案。新动作仍区分力度，自动执行通过 current 的实际变化校验位移。默认追求精确命中；服务器有容差时可设置容差，目标是该范围内的最少操作。既往已耗费的步数无法撤销，本工具不预测最终锻造奖励等级。

## 材质包与自动适配

经 TFC **v4.2.12 / Minecraft 1.21.1** 源码核对，砧界面使用 `assets/tfc/textures/gui/anvil.png` atlas，并非独立的 GUI sprite。工具按以下低到高优先级读取：

1. 实例的 TFC JAR。
2. `options.txt` 的 `resourcePacks` 列表（存储顺序从低到高，Minecraft 设置界面最上面的包优先级最高）。
3. 用户显式添加的额外包；多次指定时最后一个优先。

支持 ZIP、文件夹、等比例高清 atlas、适用于 pack format 34 的 `pack.mcmeta` overlays 和资源过滤器。普通方块包没有覆盖砧贴图时，继续使用下层资源。当前来源与兼容提示会显示在设置页。启用列表、JAR、资源包文件或已知贴图变化后会重建模板。高优先级文件包已提供砧 atlas 时，下层未知内置包无法影响该资源，自动忽略其不相关提示；高层仍可能覆盖 atlas 的未知包需要补充资源。

用户提供的 `TFCR辅助材质1.21.zip` 已验证包含砧 atlas，布局与默认版一致，增加了进度刻度。其元数据为旧的 `pack_format=15`，工具提示差异但可按显式指定读取。该 ZIP 未随项目分发，也未修改。

```powershell
# 显示自动解析出的来源
.\.venv\Scripts\python.exe -m tfc_forge_helper assets

# 显式验证单个覆盖砧 GUI 的材质包（无需启动游戏）
.\.venv\Scripts\python.exe -m tfc_forge_helper assets --pack 'C:\Downloads\TFCR辅助材质1.21.zip'

# 识别已有截图并输出方案及诊断图
.\.venv\Scripts\python.exe -m tfc_forge_helper detect --image screenshot.png --instance 'E:\Games\Minecraft\instance' --annotate work\detected.png
```

自动模式没有发现唯一实例时，指定 `--instance`。只有覆盖砧 GUI 的包可以单独使用 `--pack`；普通方块材质包需要实例/JAR 提供回退贴图。

## 校准与识别边界

“框选砧 GUI 并保存校准”支持拖动选择完整 GUI 的外边框，保存为本地 profile。校准选区固定在当前截图坐标中，移动游戏窗口、改变截图显示器或缩放后应清除或重做；默认自动定位无需此操作。

`profiles/default.json` 列出了布局字段。重新排列控件的魔改界面可修改进度条、规则、历史和定位锚点坐标。仍需提供可解析的 atlas；MVP 不支持任意重画控件的自动推断或逐图标标注训练。

识别采用 atlas 动态模板、几何位置及多候选匹配；不使用 OCR。读取 current / target、规则动作及位置条件、最近三步。连续识别中，窗口遮挡、图标相似、未选配方或匹配度不足的帧不会覆盖已有显示；保留的方案仅代表上一次成功识别的状态。F8 / 按钮手动识别失败仍清空旧方案并说明原因；修改输入、切换实例或资源时也会清除旧方案。自动打铁独立重新读取并校验屏幕，不会用保留的显示方案发送点击。显示的“匹配度”是图像相似分数，不是统计校准后的正确概率。

当前自动识别支持默认指针模式。服务器将 `anvilAcceptableWorkRange` 设置为 2 或以上时会绘制范围括号，MVP 暂需手工输入 target 和容差。独立 sprite atlas、动画 GUI、着色器改色、控制布局的其他模组、非整数缩放与未知内置包可能需要扩展适配。独占全屏截图不可用时，可使用窗口化/无边框模式。

## 实现与验证

`model.py` 定义动作和规则；`solver.py` 对 `(位置, 最近三步动作类别)` 运行 BFS。每次操作权重相同，搜索完整有限状态图，因此返回最少新增操作；每条边保留真实力度，且所有中间位置必须位于 0–150。边界 150 来自服务端实际工作检查；上游用于奖励估算的预计算表使用了不同的半开区间，本项目不直接照搬该估算。

`discovery.py` 读取进程启动信息和工作目录；`assets.py` 解析资源优先级；`vision.py` 定位和识别，并复用同一 atlas/profile 的指针及历史模板；`engine.py` 检查资源变化并缓存模板；`gui.py` 提供异步桌面窗口；`automation.py` 实现每件一次求解、序列执行、结果确认与 Windows 输入；`batch.py` 负责原料/成品识别、自动取放、数量与进度。输入接口与业务流程分离，测试使用模拟接口。

双击 `self-test.cmd` 运行测试和静态检查。测试包含独立枚举验证最短性、历史复用、所有击打力度、规则冲突、边界、资源优先级/过滤/overlay、进程路径解析、资源热更新、多缩放图像识别，以及自动执行的反馈确认、取消、不重试、焦点变化和配方重置。自动执行测试全部使用模拟输入接口。项目自带原创诊断贴图生成器；真实默认/用户样本保存在本地忽略目录 `work/reference/`，可用时运行额外集成测试。

**验证范围：** 已自动定位用户运行中的 TerraFirma Rebirth 2 实例，解析 TFC 4.2.9 和启用的辅助材质包；用户真实截图识别为 current=0、target=88、三次 hit 规则，匹配度约 99.8%，并找到快捷栏第 8 格中的同类原料。桌面界面与模拟批量流程经过验证；尚未向真实游戏发送点击或完成实机批量端到端验收。

上游来源与坐标依据见 `docs/upstream.md`。工具不会下载或修改游戏文件；项目包不包含 TFC 或用户材质包资产。
